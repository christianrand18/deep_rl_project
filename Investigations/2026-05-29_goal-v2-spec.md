**Date:** 2026-05-29

## What the round-1 evidence tells us

`soft` and `goal` at λ=0.1 both showed the **same** failure mode: meta-policy α swings or saturates at 2.0 (the upper bound), low-level raw ρ sits at the neutral ~0.5, the two are effectively decoupled. Worker shaping is too weak *and* the meta has no incentive to set achievable targets.

`cap` failed for a different (structural) reason — meta escapes to α≥1 where our ceiling-only design is a no-op. λ won't fix this. **Treat `cap` as a documented dead end.**

`multiplier` continues to exhibit the documented compensation (raw ρ ≈ 1.6 while effective ≈ 1.0).

---

## What recent HRL says (source-verified 2026-05-29)

The "manager outputs goals the worker can't reach" problem is well-known and has named recent treatments:

- **HIRO** (Nachum 2018) solves it via **off-policy goal relabeling** at the manager — when the worker achieved g', relabel the manager's action to a g' that would have produced the observed behavior. Requires off-policy manager. **Doesn't compose cleanly with our PPO meta** — this is why we're off-recipe.
- **Reachability-Based Reward Shaping** (Wang 2024) constrains the high-level to subgoals within a reachable region of demonstrated trajectories.
- **Strict Subgoal Execution** (2025) explicitly characterizes the reachability boundary of candidate subgoals and uses Frontier Experience Replay.

All three converge on the same insight: **the manager needs a cost signal for proposing what the worker can't deliver.** HIRO does it implicitly through relabeling; the 2024-25 work does it explicitly through reward shaping or action-space constraints.

Since we can't easily do off-policy relabeling (PPO), the simplest equivalent is **reward shaping on the meta** — exactly the "skin in the game" change.

## The v2 change — *exactly one new term*

**Add `--meta_track_lambda` flag** (default 0.0 = disabled, fully backward-compatible).

When > 0 *and* `--meta_action_mode in {soft, goal}*, augment the meta-policy's per-day reward:

```python
# in main_a2c_multi_agent.py, at the meta store_reward site:
meta_reward = (accumulator.profit[_a] - accumulator.reb_cost[_a]) / args.reward_scalar
if args.meta_track_lambda > 0 and args.meta_action_mode in ("soft", "goal"):
    avg_factor = 2.0 * np.mean(day_price_raw[_a])           # already collected in v1
    target     = meta_multipliers[_a]
    meta_reward -= args.meta_track_lambda * (avg_factor - target) ** 2
meta_policies[_a].store_reward(meta_reward)
```

That's the entire change. `day_price_raw` already exists from v1 Task 7. No new buffers, no new agent methods, no new layer.

### Why this is the minimum that should work

- It closes the loop: meta now experiences a *cost* when α drifts away from where the low-level actually lives. The cost is in the same units as the existing scaled profit (O(1–5)), so calibration is intuitive.
- It does *not* mess with the worker. The worker shaping (soft penalty, goal intrinsic) is unchanged — the λ sweep results stay interpretable.
- It compounds correctly with the existing worker shaping: if worker tracks better (larger λ_track), meta's tracking cost shrinks naturally — the two sides converge.
- It maps directly to the 2024-25 "reachability-based" idea: the meta is now penalized for unreachable goals, but with our defined "reachability" = actual achieved 2·ρ.

### What we are NOT doing in v2 (deliberately)

| Change considered | Verdict | Reason |
|-------------------|---------|--------|
| Hindsight goal relabeling (HER) for the worker | **Skip** | Adds buffer + replay logic. Worker is on-policy A2C — adding HER means restructuring the training loop. Out of scope for a "minimum that works" v2. |
| Off-policy meta (HIRO-style relabeling) | **Skip** | Requires swapping PPO for SAC/TD3 at meta. Huge change. |
| Smooth-out goal's saturating intrinsic (Gaussian / quadratic) | **Skip** | If meta-augmentation alone makes either soft or goal track, we don't need to touch the worker shape. If only soft tracks, drop goal as redundant. Don't pre-optimize. |
| Drop `cap` / `goal` from the code | **Defer** | Until v2 validates, leave existing modes in place. Cleanup is a follow-on PR. |
| Per-region β instead of scalar | **Skip** | Would require changes to meta-policy output dim and `lin_alpha`. Big. |

Net structural change vs v1: **+1 flag, ~5 lines of code, no new modes, no new buffers.**

## Decision criteria — unchanged from v1 spec

Primary gate (must win both):
- (crit 2) **Effective price tracks meta intent** — `corr(α_day, 2·ρ_day)` significantly positive across the 3 seeds.
- (crit 3) **Profit preserved** vs unbounded multiplier baseline (~63k for a0), within the undercut regime.

Diagnostic (per mode):
- `agent0/meta_shaping_term` (worker side, post-scale) should be bounded and decreasing across training.
- A new logged scalar `day/agent{_a}_meta_track_penalty` (post-scale) should also decrease — the meta should learn to set increasingly achievable targets.

## Resolved open questions

1. **Why not also smooth goal's saturating shape?** Deferred. If meta-augmentation gets soft tracking, goal is redundant; if it doesn't, the shape issue is moot.
2. **Why not HER?** Out of scope for "minimum that works." Future v3 if needed.
3. **Why factor-space penalty `(avg_factor − β)²` and not something fancier (e.g., bell-shaped)?** Mirrors the worker's soft penalty form for consistency. Same units (factor space ∈ [0,2]), same interpretation.
